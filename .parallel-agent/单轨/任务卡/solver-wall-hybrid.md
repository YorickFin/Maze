# 任务卡：破解端混合策略——沿墙为主 + 前沿规划兜底 + 环形观测

## 目标

在现有「视野信任 + 前沿探索」求解器之上增加混合策略，进一步降低步数与计算开销：

1. **沿墙模式（默认）**
   - 右手法则：相对当前朝向的尝试顺序为 **右 → 直 → 左 → 后**，即“优选无墙方向”。
   - 只用已知地图判断相邻格：已知墙/已知障碍直接跳过（不算步），未知相邻格则尝试；撞到灰色障碍记为已知障碍并换方向。
   - 每次成功转向后记录 `(位置, 朝向)`；若状态重复（原地打转）或四个方向都不可行，切换到规划模式。
   - 起始朝向为右。
2. **规划模式（兜底）**
   - 复用现有方向代价 Dijkstra 前沿探索；方向代价改为 **右=1、上/下=3、左=10**（评估中该组参数对难种子收益最大）。
   - 一旦从沿墙切到规划，就保持在规划模式，避免两种模式来回抖动。
3. **目标处理**
   - 红点进入视野后，无论当前模式都切到「直达规划」，直接走向红点；到达即完成。
4. **环形增量观测**
   - 初始观测完整 25×25 视野；之后每成功移动一格只观测新进入的一条 25 格视野边（右移取右列、下移取下行，依此类推）。
   - 感知结果与全量观测等价，`explored` 仍是所有视野的并集。
5. **可观测性**
   - `get_state` 增加 `mode`（`沿墙` / `规划`），顶栏状态显示当前策略。

## 非目标

- 不改迷宫生成、配色、地图传输协议（`get_map` 一次 + 增量仍沿用）。
- 不做左右手双策略对比、不做参数自适应调优。
- 不改变“只有灰色障碍不可见、红点进入视野可见”的感知语义。

## 未知项

无（路线已由用户选定，参数取自本次评估数据）。

## 假设

- 相邻格一定在历史视野内，因此沿墙只用已知地图即可判断相邻墙/障碍，不需要额外感知。
- 沿墙打转可以用 `(位置, 朝向)` 重复检测；检测到即交给规划模式，由前沿探索继续推进。
- 环形观测与全量观测在连续单格移动下等价。

## 评估数据（本次新策略的依据）

| 方案 | 20 种子到达 | 平均步数 | 计算耗时 |
|---|---|---|---|
| 现有前沿规划 1/2/4 | 20/20（8 种子实测） | 约 10k+ | 约 2.7s/种子 |
| 强右向 1/3/10 | 20/20 | 8679 | 约 2.7s/种子 |
| 右手沿墙 | 20/20，0 打转 | 7868 | 约 0.015s/种子 |

## 验收

- [ ] 20 个种子（0~19）全部到达 `maze.end`；输出每个种子的步数、受阻、耗时、是否触发兜底、最终模式。
- [ ] 至少 18/20 个种子由沿墙模式直接到达终点（未触发兜底）；触发的种子记录原因（打转/四向不可行）。
- [ ] 环形观测正确性：给定种子，遍历全部 `visited` 位置，断言其 25×25 视野内的每一格都在 `explored` 中（与全量观测等价）。
- [ ] 感知断言：随机 100 步，视野内墙 ∈ 已知墙、通道 ∈ 已知可通行、障碍不在已知集合（除非已因受阻标记）。
- [ ] 平均步数 ≤ 现强右向基线（8679 步），平均单步耗时 ≤ 0.1ms（沿墙为主时）。
- [ ] 红点进入视野后仍能直达并精确到达终点；8 个既有种子（42/7/99/123/2024/5/88/77）全部到达。
- [ ] `get_state` 含 `mode` 且顶栏正确显示；无 JS 报错；`py_compile` 通过，`uv run maze` 可启动。
