# 任务卡：破解端重构——视野信任 + 方向偏置前沿探索

## 目标

重写 `Solver`，把「朝右边界做全局 A* + 撞墙后上下左右盲扫」换成「信任视野 + 方向偏置的局部前沿探索」：

1. **不读全局**：求解器不读取地图宽高，不预先知道终点坐标；只维护「目标方向偏右」这一先验。红点是可见标记，进入 25×25 视野后才记录其位置并直接规划过去。
2. **感知信任**：每步观测以自身为中心 25×25 范围。墙→已知墙；可通行→已知可通行（完全信任）；灰色障碍→保持未知（唯一不可见信息）。
3. **规划**：Dijkstra 只在已知可通行格上扩展，方向代价 **右=1、上/下=2、左=4**；目标是「已知可通行且与未知格相邻的前沿」。找到前沿后踏入未知格：
   - 成功 → 新视野并入已知图，继续；
   - 受阻 → 该格记为「已知障碍」（灰），清空当前路径并从当前位置重新规划。
4. **删除盲扫**：移除原 `_replan` 的四邻试探；任何重规划都沿已探明路径回溯，不再逐步戳四周。
5. **卡死判定**：仅当从当前位置经已知可通行格再也到不了任何前沿时判卡死。
6. **演示层终止**：红点进入视野后求解器直接规划过去；`Api` 检测 `pos == maze.end` 判「完成」（求解器只认「看到的红点」，不读地图边界）。

同时做三处配套改造：

- `view_size` 配置为 25×25。
- 状态传输：`get_map()` 首帧返回一次 `grid`；`get_state()` 只返回位置/步数/受阻/状态与增量集合（新探索、新走过、新墙、新推断障碍）。
- 三栏渲染适配新语义：中栏墙黑/通道白/推断障碍灰/未推断障碍仍白；左栏已探索白、已知墙黑、推断障碍灰、轨迹蓝；右栏底图只绘制一次，每帧只叠加轨迹与标记。

## 非目标

- 不改迷宫生成算法与配色（沿用 S-20261107-004）。
- 不读取真实障碍位置做规划（只在「移动受阻」时确认障碍）。
- 不实现真实传感器、不做多算法对比、不导出结果文件。
- 求解器不感知地图边界尺寸；代码中的数组越界防护只用于避免索引异常，不参与目标判定。

## 未知项

无（终点认知、视距、传输优化三项已由用户确认）。

## 假设

- 视野内的墙和可通行格都能被立即感知；视野内的灰色障碍不可见，只能靠一次受阻确认。
- 迷宫生成保证了起点→终点存在一条不被灰斑切断的通路，因此前沿探索最终能到达终点。
- 方向代价按「进入该格的移动方向」计：向右 1、向上/下 2、向左 4。

## 候选方案

已在提问阶段收敛，采用「方向代价 Dijkstra + 前沿目标 + 已探明路径回溯」。
