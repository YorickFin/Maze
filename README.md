# Maze · 迷宫破解演示

一个「有机形态迷宫 + 在线破解」的可视化演示：后端用 Python 生成手绘风格迷宫并模拟带视野限制的破解方，前端用 Vue 3 实时展示「已探索 / 实时视野 / 完整地图」三栏。

破解方不知道地图尺寸、也不知道终点坐标，只依靠有限的视野边走边推断，并在三种探索策略之间切换。

前端完整地图上用紫色标出该地图的最短路径，作为给用户参考的「标准答案」。

---

## 功能特性

- **有机迷宫生成**：抖动节点阵列 + Kruskal 生成树保证连通，圆盘笔刷填充宽窄不一的通道与膨大腔室，按概率加入环路；通道内投放灰色障碍斑块，并沿最短路径保留保护带，避免切断主通路。
- **受限感知**：视野边长可调（默认 25×25）。视野内墙与通道可见，**灰色障碍不可见**，撞上后才确认；红点终点进入视野后才获得坐标并转为直达规划。
- **三种探索策略**（可在运行时下拉切换）：
  - **沿墙**：右手法则，支持四向 / 八向；八向采用「贴墙优先 + 开阔直行兜底」，允许擦单侧墙角但禁止穿双墙对角缝隙。
  - **前沿规划**：方向代价 Dijkstra（右 1 / 上下 3 / 左 10）走向前沿，疑似障碍附加高代价。
  - **聚类信息增益**：前沿按连通性聚类，用一次 Dijkstra 评估最近 K 个簇，按「信息增益 − 路径代价」选目标（默认策略）。
- **四向 / 八向移动**：规划模式严格禁止切角；对角代价为 √2。
- **运行控制**：开始 / 换图 / 暂停 / 速度 / 视野滑块 / 策略切换 / 移动模式切换；换图会重新生成地图并重算最短路径。
- **增量传输**：地图只在启动或换图时下发一次，之后每帧只传增量，保证大图下依然流畅。

## 快速开始

### 环境要求

- Python 3.15+（见 `pyproject.toml`）
- Node.js 与 pnpm（建议 Node 22+，前端使用 Vite 8）
- 依赖统一装在项目本地环境，不做全局安装

### 安装与运行

```powershell
# 1. 安装 Python 依赖（uv 会创建/同步 .venv）
uv sync

# 2. 构建前端（dist 不入库，必须构建后才能运行）
Push-Location frontend
pnpm install
pnpm build
Pop-Location

# 3. 启动桌面程序（pywebview 窗口）
uv run maze
```

开发前端时可用热更新：

```powershell
Push-Location frontend
pnpm dev
Pop-Location

# 另开一个终端
$env:MAZE_FRONTEND_URL = "http://localhost:5173"
uv run maze
```

## 操作说明

| 控件 | 作用 |
|---|---|
| 开始 | 不换地图，重置已探索与实时视野后从起点重新跑 |
| 换图 | 换随机种子生成新地图，等待点击「开始」后再跑 |
| 暂停 / 继续 | 暂停或恢复推进（未开始时不可用） |
| 策略 | 聚类 gain / 沿墙 / 前沿规划 |
| 移动 | 8 向 / 4 向 |
| 速度 | 每帧推进的步数（1~100） |
| 视野 | 视野边长 10~100 |

界面三栏：

- **已探索**：黑=墙/未知，白=通道，灰=推断障碍，蓝色为实际轨迹。
- **实时视野**：当前 25×25 视野内的墙、障碍与轨迹。
- **完整地图**：全图黑/白/灰三态，紫色为最短路径，黄圈为当前位置。

## 配置

所有运行参数集中在 `config.toml`，修改后重启程序生效（界面上切换的策略/视野/移动模式不写回配置）。

| 分组 | 关键字段 | 说明 |
|---|---|---|
| `[maze]` | `width` / `height` | 网格宽高（格） |
| `[generator]` | `seed` | 随机种子，`-1` 表示每次随机 |
| | `node_spacing` / `node_jitter` | 节点阵列间距与抖动 |
| | `corridor_radius_min/max` | 通道半径范围 |
| | `chamber_radius_min/max` / `chamber_prob` | 节点腔室半径与出现概率 |
| | `loop_prob` | 额外环路概率 |
| `[obstacle]` | `blobs` / `radius_min` / `radius_max` | 灰色障碍斑块数量与半径 |
| `[solver]` | `view_size` | 破解方视野边长 |
| | `cost_right` / `cost_vertical` / `cost_left` | 方向代价（默认 1 / 3 / 10） |
| | `suspect_penalty` | 穿过疑似障碍格的附加代价 |
| | `allow_diagonal` / `diagonal_factor` | 八向开关与对角代价系数 |
| | `wall_follow` / `cluster_enabled` | 默认策略开关 |
| | `cluster_*` | 聚类信息增益参数（权重、簇大小、top_k、评估半径与上限） |
| | `plan_expand_limit` / `max_steps` | 单次规划扩展上限与总步数上限 |
| `[visual]` | `cell_px` | 画布中每格像素大小 |

## 已知限制

- 灰色障碍对传感器不可见，只能靠撞击确认；因此「已观测但未知」的格在规划中按疑似障碍处理。
- 破解方不读地图尺寸与终点坐标，只看视野；红点进入视野后才获得终点。
- 八向沿墙允许擦单侧墙角（规划模式仍严格禁止切角），两者规则有意分离。
- 完整地图上的最短路径是 4 连通 BFS 结果，不是八向最短路径。
- `frontend/dist` 不入库，每次前端改动后需要重新 `pnpm build`。
- 本项目是本地桌面演示（pywebview + 本地静态服务），没有服务端部署形态。
